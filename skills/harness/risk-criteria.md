# リスクゾーン判定基準

harness フローで AI が自律前進してよいか／人間が確認すべきかを決めるための共通基準。
変更の**リスク**で 3 ゾーンに分ける。判定は **ファイルパスではなく「その変更が何をするか（振る舞い・意味）」**で行う。
UI コンポーネントやページに重要なロジックが書かれることもあり、**置き場所はリスクの代理にならない**。
ゾーンは「その変更が触れる最もリスクの高い要素」で決める（複数該当なら上位ゾーンを採る）。
**迷ったら上位ゾーン（厳しい側）に倒す。**

| ゾーン     | 意味                 | 振る舞い                                                                                                |
| ---------- | -------------------- | ------------------------------------------------------------------------------------------------------- |
| 🔴 Danger  | 人間が必ず見る       | **作業を止めてユーザーに上げる**（論点・影響範囲・選択肢・推奨案・自律確定できなかった理由を提示） |
| 🟡 Caution | サマリーで人間が確認 | 自律で進めるが、**コミットメッセージに必ず明記**（マージ時レビューで効く）                              |
| 🟢 Free    | ノールック           | 完全自律。特記不要                                                                                      |

---

## 🔴 Danger Zone（実行中に停止・人間レビュー必須）

その変更が以下のいずれかを**する**なら Danger。止めてユーザーに上げる。

- **認証・認可・権限**: 認証 / セッション / パスワードハッシュのロジック、権限チェック（所有者・ロール判定）の追加・変更・削除
- **お金**: 課金・決済・残高・従量コストが動く処理
- **個人情報・機密・シークレット**: PII や機密データの保存・ログ出力・外部送信、API キー / 署名鍵 / 暗号鍵の扱い変更・新規導入
- **削除系・不可逆**: データの一括削除 / 改変、本番・ステージングへのデプロイや DB 書き込み、既存マイグレーションの改変・破壊的スキーマ変更、`git push --force` / `git reset --hard` / ブランチ削除
- **外部との契約**: 公開済み API（HTTP / モジュール公開 API）のシグネチャ変更・削除
- **DB スキーマ**: スキーマを変えるマイグレーション（テーブル / カラム / 制約の追加・変更・削除）
- **セキュリティ境界**: 入力バリデーション / サニタイズ境界、CSRF / CORS / CSP / Cookie 属性などセキュリティ関連ヘッダーの変更

## 🟡 Caution Zone（自律で進めるがコミットメッセージに明記）

影響はあるが可逆で、破壊的でないもの。実行中は止めない。**コミットメッセージの「設計判断」「影響範囲」「自信のない箇所」に必ず書き出し**、マージ時のサマリーレビューに載せる。

- **外部連携**: 外部システム（LLM・メール等）を**新たに呼び始める**、または呼び出しパターンを大きく変える
- **境界の追加**: モジュール公開 API・モジュール境界の**新規追加**（破壊でなく追加）
- **共有レイヤー**: 共通型・共通ユーティリティへの新規追加
- **依存・インフラ**: 新しいライブラリ / 依存の追加、インフラ設定やバインディング（KV / D1 / R2 / Queue など）の追加・変更（コスト・構成に影響）
- **規約逸脱**: 既存の実装パターン（エラーハンドリング方針・命名規約・依存注入方針）からの逸脱

## 🟢 Free Zone（ノールック・自律）

外から観測できる振る舞いを変えない、または局所的で可逆なもの。

- 既存の振る舞いを変えない内部リファクタ
- テストの追加・修正
- ドキュメントの追加・修正
- UI の見た目・レイアウト・文言の調整（認可表示やデータ操作を伴わないもの）

## ゾーンに依らず止める論点

リスク要素には触れていなくても、以下に該当したら Danger 同様に止めてユーザーに上げる。

- **仕様の曖昧さ**: 複数の妥当な解釈が併存し、どれも合理的で AI が優劣を決められない
- **スコープ逸脱**: 「小さな変更」のはずが差分が広範囲に及ぶ／当初範囲を超えるリファクタが要る（元タスクは完了させ、追加分は別 spec として提案する）
- **性能・非機能の悪化**: N+1（ループ内 DB / 外部 API 呼び出し）、ページネーション無しの全件ロード、リクエスト処理中の長時間ブロッキング、キャッシュキー設計の変更

## エスカレーション時に出すもの

🔴 Danger / ゾーンに依らず止める論点に該当した場合の報告フォーマット。

- 論点（何を判断してほしいか）
- 影響範囲
- 選択肢（複数案がある場合）
- 推奨案と理由
- なぜ自律確定できなかったか
