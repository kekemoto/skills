# walkthrough — 段階的な読み合わせ解説

長い文書を一気に説明せず、**小さく区切って・確認を取りながら**読み合わせていくためのスキル。

## 対象の特定

引数 `$ARGUMENTS` を見て、解説対象を決める。

- **ファイルパスが渡された場合**（例: `/walkthrough docs/xxx.md`）→ そのファイルを Read で読む
- **テキストが直接貼られた場合** → そのテキストを対象にする
- **引数が空、または曖昧な場合** → 直近の会話で参照中の文書・出力を対象にしてよいか確認する。対象が見つからなければ「何を解説しますか？」と尋ねる

## 進め方（最重要）

1. 対象全体を最初に読み込む（途中で情報が足りなくならないように）。
2. **数行分のまとまり（1つの論点・段落・箇条書き 2〜3項目程度）ごと**に区切って解説する。
3. 各区切りの解説を出したら、**必ず `ここまでOK？` のような確認を出して、そこで止まる**。ユーザーの了承を待つ。
4. 了承（「OK」など）が来たら、次の区切りへ進む。
5. ユーザーから**質問が来たら、まずそれに回答する**。回答後、了承が取れてから次へ進む。
6. 全体が終わったら、**最後に全体像を箇条書きで短くまとめる**。

## 解説スタイル

- **文章は分かりやすく言い換えてよい。ただし情報量を絶対に落とさない**。原文の論点・条件・数値・固有名詞はすべて残す。
- 専門用語は必要に応じてかみ砕く（例: 「rule of three = 3回現れたら抽象化する原則」のように括弧で補足）。
- 1区切りは「読んで疲れない量」を意識する。長すぎる区切りは避ける。
- 見出しや絵文字で区切りを視覚的に分かりやすくしてよい。
- 原文と現状が食い違う点に気づいたら、解説の中で補足として明示する（例: 「レポート時点では X だが、現在は Y に変わっている」）。

## 禁止事項

- 確認を取らずに複数区切りを一気に出すこと。
- 「要するに〜」で済ませて中身の情報を省略すること（要約スキルではない）。
- ユーザーの了承前に勝手に次へ進むこと。
